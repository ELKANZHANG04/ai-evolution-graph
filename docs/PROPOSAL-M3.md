## 一、主题关系展示（不止线性分类）

当前：思想看板 = 7 个主题纵向分区 + 主题内线性步骤链。跨主题关系（"规模之争"与"世界模型之争"互相支撑/对立）目前看不到。

### 方案对比

| 方案 | 形式 | 优点 | 缺点 |
|---|---|---|---|
| **A. 主题关系图**（推荐） | 节点 = 主题（大小 = 引文数），边 = 跨主题关系（共享方法 / 观点对立 / 迁移），点击主题跳到对应分区或筛选 | 一眼看到哪些主题在互相拉扯；可缩放、可拖动；与看板互补 | 需要维护跨主题关系数据（可半自动） |
| B. 主题 × 时间矩阵 | 横轴年份、纵轴主题的密度热力图，点格看条目 | 能看出"哪个时代哪些主题活跃"，分析感强 | 偏统计，叙事性弱 |
| C. 问题线（Threads） | 跨主题叙事线（如"规模 vs 推理""理解 vs 生成""开放 vs 安全"），选中后高亮所有相关卡片 | 最适合讲故事、最能体现"思想递进/推翻" | 需要人工策展问题线 |

**推荐组合**：看板保持默认；顶部加两个入口——「主题关系图」（A）+「问题线」筛选（C）；矩阵（B）作为补充统计，放到 M4/关于页。
- 数据模型：`src/lib/themeGraph.ts` 配置 `theme_links`（7 个主题，约 10–12 条边，每条含 `type: 共享方法 | 观点对立 | 时代迁移 | 产物复用` 与一句话理由）；另自动生成弱边（两个主题共享同一 context 事件时，如 GPT-4 同时出现在"世界模型"与"开源"链）。
- 交互：点击主题节点 → 看板滚动/筛选到该主题；hover 边 → 显示两端主题与理由；与现有主题筛选 chips 联动。
- 后续可把每日更新中的"创新点"自动挂到主题关系图上（新主题自动出现）。

## 二、创新雷达（收集未被充分重视的新想法）

### 定位
思想看板的第二层视角：不是"已发生的大事"，而是"**信号**"——有启发、但还没被主流充分讨论/产品化的想法。适合每天更新时顺手收集。

### 数据模型（frontmatter 可选字段，不改变现有 schema 语义）
```yaml
type: insight
innovation: true            # 进入创新雷达
maturity: paper | prototype | product   # 成熟度
why_underrated: "为什么还没被充分重视（1–2 句）"
thought_chain: interaction | generative-decision | ...   # 新主题可扩展
```
- 展示：思想看板新增 tab「创新雷达」：卡片 = 一句话洞察（thought_claim）+ 为什么被低估 + 成熟度标签 + 1–2 个一手来源 + 关联主题；可按成熟度/主题过滤；「新增」浮出由每日更新写入。
- 采集流程（并入每日更新）：除新闻外，增加"低热度信号扫描"（arXiv 最新、会议、GitHub trending、研究者博客）；每条必须 1 手来源、默认 `needs_review: true`，人工确认后转正；宁缺毋滥。
- 不做：不做热度排名、不做自动摘要堆砌——价值观仍然是"值得记住的想法"，不是信息流。

### 首批种子（已核实，可立即入库）
1. **全双工对话：模型学会边听边说、可被打断**
   - 关键细节：LSLM《Language Model Can Listen While Speaking》(AAAI 2025, 2025-04-11, DOI 10.1609/aaai.v39i23.34665) —— listening + speaking 双通道；token-based decoder-only TTS + streaming SSL encoder；early/middle/late 三种融合，middle fusion 在语音质量与实时交互间最平衡；支持 command-based 与 voice-based 两种打断设定。
   - 为什么值得收：对话式 AI 的"轮流说话"假设正在被打破；打断/被插嘴是实时语音交互的核心体验，也是 agent 与人类协作的基础能力。
   - 延伸（2026 待核实）：Audio-Interaction 实时对话引擎、F-Actor 全双工对话行为（ACL 2026 findings）。
2. **扩散语言模型做 agent：可编辑的计划状态**
   - 关键细节：DiffuPlan (arXiv:2610.24717, 2026-10-17) —— dLLM agent 不必模仿"只能追加"的 AR 交互协议；维护单一可编辑 planning state，新证据到来时只重建受影响步骤；Expansion-Partition Marginalization (EPM) 支持变长修订；4 个多跳 QA 基准平均 F1 50.24，同数据下 editable state 对 diffusion agent 提升 +2.44 F1（AR 源模型仅 +0.47）。
   - 补充：Metacognitive Decoding (arXiv:2610.37642, 2026-10-27) —— 扩散 agent 的推理时算力控制器，"何时定稿、生成多长"按需决定，平均推理 FLOPs −20.6%，任务精度保持。
   - 为什么值得收：agent 的计划通常是"append-only 的文本"，而扩散模型天生擅长"按上下文重建中间状态"——这可能是一种被忽视的 agent 架构优势。
3. **候选清单（QA 已核实来源，可作为创新雷达首批种子；均为一手 arXiv/官方页）**

| 主题 | 创新点 | 来源 | 成熟度 |
|---|---|---|---|
| 交互范式 | **Audio-Interaction / SoundFlow**：语音模型从回合制应答变成「常听 + 主动插话」的持续交互体（StreamAudio-2M 302k 小时、Proactive-Sound-Bench） | arXiv:2606.05121（2026-06-03） | paper |
| 交互范式 | **F-Actor**：抢话、附和、开场等「对话行为」可像提示词一样显式控制（2000h 数据，模型/代码开源） | arXiv:2601.11329（2026-01-16） | prototype |
| 智能体工具 | **DuplexSLA**：把工具调用塞进语音流——边听、边说、边调工具（160ms 同钟 timeline） | arXiv:2605.20755（2026-05-20） | prototype |
| 开源生态/交互 | **BayLing-Duplex**：不改架构，用少量特殊 token 让单个自回归 LLM 自主抢答/停顿（基于 GLM-4-Voice） | arXiv:2606.14528（2026-06-12） | prototype |
| 生成式决策 | **Plan-and-Patch**：计划天生可编辑，扩散 LM 并行去噪正好匹配局部修补（修复成功率 53.7% vs AR 27.0%，延迟 −39~46%） | arXiv:2610.10786（2026-10-07） | paper |
| 生成式决策 | **DLLM Agent**：只换扩散骨干、不动 agent 框架，端到端快 30%+（极端 8x），但结构化 tool-call 更易失败 | arXiv:2602.07451（2026-02-07） | paper |
| 记忆与持续学习 | **Nested Learning / HOPE**：把持续学习重写成多层嵌套优化，不同更新频率的层构成连续记忆 | Google Research 博客（2025-11） | paper+prototype |
| 效率与推理 | **Sleep-time Compute**：把思考放到「睡觉时」，离线预计算上下文，测试时更省算力 | arXiv:2504.13171（2025-04） | paper |
| 评估与安全 | **Petri**：用 agent 审计 agent，把对齐评估变成可并行、可复现的自动红队 | Anthropic（2025-10） | product/开源 |

> 备注：以上为 2025–2026 信号，热度尚低；入库时默认 `needs_review: true`，由人工确认后转正。用户点名的两条（LSLM / DiffuPlan）已在上文详述。
